1. 降低锁的争用来提高性能的常用方法为：**拆分数据结构和锁** 。例如在xv6的物理内存分配时，采用的是一个位于内存中的list和一个自旋锁来保证数据结构的不变性。
    1. 这时可以为每个CPU维护一个空闲list，每个list都有自己的锁。因为每个CPU将在不同的list上运行，不同CPU上的分配和释放可以并行运行。
    2. 可能遇到的**问题**：当某个CPU的list为空时，需要扫描别的CPU的list，对仍有空闲的内存的CPU list进行窃取。
    ```c
    struct {
        struct spinlock lock;
        struct run *freelist;
    }kmems[NCPU];
    //分配内存    
    void * kalloc(void)
    {
        push_off();//关中断
        int id = cpuid();
        pop_off();//开中断
        struct run *r;

        acquire(&kmems[id].lock);
        r = kmems[id].freelist;
        if(r){
            kmems[id].freelist = r->next;
            release(&kmems[id].lock);
        }
        else{
            release(&kmems[id].lock);//释放锁，避免死锁
            for (int i = 0; i < NCPU; ++i) {
                if (i == id)
                    continue;
                acquire(&kmems[i].lock);
                r = kmems[i].freelist;
                if (r){
                    kmems[i].freelist = r->next;
                    release(&kmems[i].lock);
                    break;    
                }
                release(&kmems[i].lock);
            }
        }

        if(r)
            memset((char*)r, 5, PGSIZE); // fill with junk
        return (void*)r;
    }
    //释放内存
    void kfree(void *pa)
    {
        push_off();
        int id = cpuid();
        pop_off();    
        struct run *r;

        if(((uint64)pa % PGSIZE) != 0 || (char*)pa < end || (uint64)pa >= PHYSTOP)
            panic("kfree");

        // Fill with junk to catch dangling refs.
        memset(pa, 1, PGSIZE);

        r = (struct run*)pa;

        acquire(&kmems[id].lock);//需要锁，因为别的CPU可能正在请求当前CPU的内存
        r->next = kmems[id].freelist;
        kmems[id].freelist = r;
        release(&kmems[id].lock);
    }        
    ```
