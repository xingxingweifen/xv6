1. 当用户程序调用系统函数时，需要打断用户程序的执行进入内核空间进行执行。当系统调用执行完毕，我们自然是想要继续执行用户进程的，那么为了能够进入内核执行程序并在结束后继续执行用户进程的代码，**我们大概需要做那些事呢**？
   1. 保存各种寄存器；
   2. 保存程序计数器；
   3. 切换页表；
   4. 设置内核栈。
   <br>

2. RISC-V 指令集中专门提供了ecall指令以从用户空间进入内核空间。比如当调用系统调用read时的汇编代码如下。ecall 只做以下**三件事**。显然距离在内核中执行代码还差的远，这么做的原因是为了尽可能的灵活。
   1. 从用户态切换为内核态
   2. 将程序计数器保存到SEPC寄存器当中
   3. 将STVEC寄存器的值赋值给PC程序计数器
```c
read:
    li a7, SYS_read ; 将对应的系统调⽤号放到a7寄存器中
    ecall ; 执⾏中断隐指令进⼊内核
    ret ; 返回到调⽤系统调⽤的下⼀条指令
```
<br>

3. ecall将PC赋值为STVEC的值后，程序就会跳转到trampoline页执行uservec函数。在其中进行**寄存器保存**、**设置内核栈**、**切换页表**的操作。**这里一个有意思的点在于**，切换页表后，程序竟然没有崩溃。
```
uservec:    
	#
        # trap.c sets stvec to point here, so
        # traps from user space start here,
        # in supervisor mode, but with a
        # user page table.
        #
        # sscratch points to where the process's p->trapframe is
        # mapped into user space, at TRAPFRAME.
        #
        
	# swap a0 and sscratch
        # so that a0 is TRAPFRAME
        csrrw a0, sscratch, a0

        # save the user registers in TRAPFRAME
        sd ra, 40(a0)
        sd sp, 48(a0)
        sd gp, 56(a0)
        sd tp, 64(a0)
        ....

	# save the user a0 in p->trapframe->a0
        csrr t0, sscratch
        sd t0, 112(a0)

        # restore kernel stack pointer from p->trapframe->kernel_sp
        ld sp, 8(a0)

        # make tp hold the current hartid, from p->trapframe->kernel_hartid
        ld tp, 32(a0)

        # load the address of usertrap(), p->trapframe->kernel_trap
        ld t0, 16(a0)

        # restore kernel page table from p->trapframe->kernel_satp
        ld t1, 0(a0)
        csrw satp, t1
        sfence.vma zero, zero

        # a0 is no longer valid, since the kernel page
        # table does not specially map p->tf.

        # jump to usertrap(), which does not return
        jr t0
```
<br>

4. 之后会从uservec跳转到usertrap函数中，函数首先保存SEPC寄存器的值在p->trapframe->epc中，接着判断引起中断的原因是什么，若是系统调用，则会调用syscall()函数，syscall函数根据寄存器p->trapframe->a7的内容获得系统调用号。在内核中存储了一个系统函数表，根据系统调用号就可以索引到系统调用函数。
<br>

5. 之后会进入usertrapret函数，这个函数为用户程序下次进入内核中而做准备。并在最后跳转回trampoline页中，执行userret。
```c
  // send syscalls, interrupts, and exceptions to trampoline.S
  w_stvec(TRAMPOLINE + (uservec - trampoline));

  // set up trapframe values that uservec will need when
  // the process next re-enters the kernel.
  p->trapframe->kernel_satp = r_satp();         // kernel page table
  p->trapframe->kernel_sp = p->kstack + PGSIZE; // process's kernel stack
  p->trapframe->kernel_trap = (uint64)usertrap;
  p->trapframe->kernel_hartid = r_tp();         // hartid for cpuid()
...
  // set S Exception Program Counter to the saved user pc.
  w_sepc(p->trapframe->epc);

  // tell trampoline.S the user page table to switch to.
  uint64 satp = MAKE_SATP(p->pagetable);

  // jump to trampoline.S at the top of memory, which 
  // switches to the user page table, restores user registers,
  // and switches to user mode with sret.
  uint64 fn = TRAMPOLINE + (userret - trampoline);
  ((void (*)(uint64,uint64))fn)(TRAPFRAME, satp);
```
<br>

6. userret会首先切换页表，然后恢复寄存器。最后使用sret指令，将SEPC寄存器的值赋值给PC程序计数器，并从内核态切换回用户态。
