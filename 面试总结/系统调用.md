# 系统调用过程
1. 用户态执行系统调用
2. 在RISC-V(Reduced Instruction Set Computer)中有一个叫做ecall的指令专门来实现从用户态切换到内核态。
3. ecall指令的主要工作为：1.将用户态切换为内核态；2.保存用户程序的程序计数器（保存到SEPC寄存器）以及记录trap的原因；3.将PC（从STVEC寄存器中拷贝）切换为trampoline.S中的uservec函数的地址。([几种重要的寄存器](./extra/trap中涉及到的重要寄存器.md))
4. 这里一个有意思的点是ecall只为我们做了一点点工作，像保存用户程序使用过的寄存器、将用户页表切换为内核页表、将SP寄存器的内容指向kernel stack。等等这些工作都没有做。这么做的原因在于是为了提供尽可能的灵活性。[ecall只实现一部分的原因](./extra/ecall只实现一部分工作的原因.md)
5. uservec函数的作用就是继续ecall的工作，保存寄存器（保存到进程的trapframe中），切换user page 为 kernel page ，设置内核栈。这里有意思的另一个点是：切换pagetble之后为什么程序并没有崩溃？这里的PC并没有变化保存的仍然是用户程序的虚拟地址，这里没有崩溃的原因是不论是在user pagetable还是 kernel pagetable 的trampoline都映射到同样的物理地址。最后uservec跳转到usertrap函数中。
6. 在usertrap函数中会首先对中断产生的原因进行判断，针对系统调用，会进入syscall函数，内核中根据系统调用编号索引一个函数指针表完成系统调用。
7. 执行完系统调用后，会回到usertrap函数当中，之后会进入usertrapret函数当中，usertrapret需要为用户程序做好下一次使用系统调用进入内核时的准备工作。像设置trampframe中的内核页表地址，内核栈指针，kernel_trap指针（指向usertrap，这样uservec才能跳转到usertrap），设置SEPC寄存器的置为保存的值。
8. usertrapret最后会跳转会trampoline.S当中，完成页表切换回user pagetable和恢复寄存器的工作最后回到（sret）用户程序中断的地方。（仔细想想，先切换页表还是先恢复寄存器还是有讲究的，因为在SSRATCH寄存器中保存的值为用户程序的trampframe的首地址，必须要用到用户页表）
